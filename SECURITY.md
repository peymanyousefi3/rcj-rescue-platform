# Security

Do not post passwords, access tokens, team submissions, private replay URLs, database exports or participant information in public issues.

Report a suspected vulnerability through a private GitHub vulnerability report if enabled, or contact the repository owner through an established private channel. Include the affected version, reproduction steps, impact and a minimal example without real participant data. Do not test other teams' live data without permission.

## Deployment responsibilities

Use HTTPS, fresh secrets, supported dependencies, private storage, malware scanning, backups and least-privilege accounts. Configure mail and optional storage credentials outside version control. Review uploaded HTML recording packages as active content; preserve the application's validation, authorized asset serving and iframe protections. Never expose private media as an unrestricted static directory.

The included tests cover many authorization, deadline, upload, scoring and replay cases. Passing tests are not a guarantee that an installation is secure. Recheck access after changing recipients and verify public-release controls before publishing competition material.
